# 消息类型体系：UserMessage / AssistantMessage / ToolResultMessage

## 要学习什么

XingClaw 定义了三种消息类型来统一不同 AI provider 的输入输出格式。理解这三种消息的职责和关联方式，是看懂 agent 工作流程的基础。

## 概念解释

### 三种消息的职责

- **UserMessage** — 用户发送的消息。包含用户的输入内容。
- **AssistantMessage** — AI 模型的回复。包含文本、思考过程或工具调用，同时记录 token 用量和停止原因。
- **ToolResultMessage** — 工具执行完返回的结果，通过 `tool_call_id` 和 AssistantMessage 中的 ToolCall 配对。

### UserMessage — 用户发消息

```python
@dataclass
class UserMessage:
    role: Literal["user"] = "user"
    content: Union[str, list[UserBlock]] = ""
    timestamp: int = 0
```

`content` 可以是字符串（纯文本），也可以是列表（文本 + 图片等组合）。发送图片时就用 `list[UserBlock]` 形式。

```python
# 纯文本
msg1 = UserMessage(content="你好")

# 带图片
msg2 = UserMessage(content=[
    TextContent(text="这张图里有什么？"),
    ImageContent(data="base64...", mime_type="image/png"),
])
```

### AssistantMessage — AI 的回复

```python
@dataclass
class AssistantMessage:
    role: Literal["assistant"] = "assistant"
    content: list[AssistantBlock] = field(default_factory=list)
    usage: Usage = field(default_factory=Usage)
    stop_reason: StopReason = "stop"
    error_message: Optional[str] = None
    # ... 还有 api, provider, model, response_id, timestamp 等字段
```

AssistantMessage 是信息最丰富的消息类型：
- **`content`** 是 `list[AssistantBlock]`，可以同时包含文本、思考过程和工具调用
- **`usage`** 记录了这次回复消耗了多少 token（包含成本统计）
- **`stop_reason`** 表示为什么停止生成：normal、length、toolUse、error、aborted
- **`error_message`** 出错了会带上错误信息

```python
msg = AssistantMessage(
    content=[TextContent(text="北京今天晴天，25°C")],
    usage=Usage(input=10, output=20),
    stop_reason="stop",
)
```

### ToolResultMessage — 工具执行结果

```python
@dataclass
class ToolResultMessage:
    role: Literal["toolResult"] = "toolResult"
    tool_call_id: str = ""
    tool_name: str = ""
    content: list[ToolResultBlock] = field(default_factory=list)
    is_error: bool = False
```

当 AI 决定调用一个工具时，它会在 AssistantMessage 中放一个 `ToolCall`，系统执行完工具后通过 `ToolResultMessage` 把结果送回。

### 关键关联：tool_call_id

```
AssistantMessage 中的 ToolCall
  -> id = "call_001", name = "get_weather", arguments = {"city": "北京"}

系统执行工具后，把结果通过 ToolResultMessage 送回

ToolResultMessage
  -> tool_call_id = "call_001"（跟上面的 id 配对）
  -> tool_name = "get_weather"
  -> content = [TextContent(text="北京 晴 25°C")]
```

**一句话：** `ToolResultMessage.tool_call_id` 对应 `ToolCall.id`，这就是"哪个工具调用返回了哪个结果"的关联键。

### 消息联合类型

```python
Message = Union[UserMessage, AssistantMessage, ToolResultMessage]
```

`Context` 中的 `messages` 字段就是 `list[Message]`，三种消息按顺序排列组成完整的对话历史。

## 总结

- UserMessage：用户输入，content 可以是字符串或列表
- AssistantMessage：AI 回复，信息最丰富（usage、stop_reason、content 列表）
- ToolResultMessage：工具执行结果，通过 `tool_call_id` 和 ToolCall 配对
- 三种消息通过 `Message = Union[...]` 合并，统一处理
