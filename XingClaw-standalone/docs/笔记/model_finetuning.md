# 模型微调（Fine-tuning）

## 一句话解释

模型微调是指：在已经训练好的大模型基础上，使用特定领域或特定任务的数据继续训练，使模型适应新的任务需求、输出格式或行为规范。

可以简单理解为：

```text
预训练：教模型通用语言能力和世界知识
微调：  教模型如何在特定场景下工作
```

例如，通用大模型可以回答一般问题；通过医疗、客服、代码审查或法律文书数据微调后，可以更稳定地使用对应领域的术语、流程和输出格式。

## 1. 为什么需要微调

### 1.1 改变模型行为

普通模型可能这样回答：

```text
用户：你好
助手：你好，有什么可以帮助你的吗？
```

客服微调后，可以稳定遵循企业话术：

```text
用户：你好
助手：您好，这里是 XX 智能客服，请问您遇到了什么问题？
```

### 1.2 提升专业领域能力

通用模型能够解释“芯片封装”，但回答可能比较宽泛。经过半导体领域数据微调后，模型可以更熟悉：

- FC 封装
- 2.5D/3D 封装
- TSV 技术
- Chiplet 架构

微调通常更适合让模型掌握领域表达、任务模式和回答风格；对于经常变化的事实知识，仍然应该优先考虑 RAG。

### 1.3 学习稳定的任务格式

例如企业希望合同风险分析始终输出：

1. 合同类型
2. 风险条款
3. 风险等级
4. 修改建议

通过高质量样本微调，模型可以更稳定地遵循这种结构，而不必每次只依赖很长的 Prompt。

## 2. 预训练、微调与推理

### 2.1 预训练（Pre-training）

预训练的目标是让模型获得通用语言能力、代码能力和大量模式知识。数据通常包括网页、书籍、论文、新闻和代码，规模可能达到数千亿 token 甚至更大。

以自回归语言模型为例，训练过程是：

```text
文本
  -> Transformer
  -> 预测下一个 token
  -> 计算损失
  -> 更新参数
```

例如：

```text
输入：北京是中国的
目标：首都
```

模型会根据预测误差调整参数。

### 2.2 微调（Fine-tuning）

微调使用比预训练少得多的任务数据，继续优化已经训练好的模型。例如：

```text
用户：介绍一下公司产品 A
助手：产品 A 是一款……
      主要优势……
      适合场景……
```

模型学习的是“任务描述如何对应到目标输出”，而不是从零开始学习语言。

### 2.3 监督微调（SFT）

最常见的微调方式是监督微调（Supervised Fine-Tuning，SFT）。训练数据中包含输入和期望输出，模型通过降低目标输出的预测损失来学习任务行为。

## 3. 微调的本质

可以把模型表示为：

```text
输出 = Model（输入，参数 θ）
```

微调的目标是让参数从 `θ` 变为更适合特定任务的 `θ'`：

```text
Model（输入，θ'）
```

相比原始模型，新的参数应当更符合目标领域的任务要求。实际工程中通常需要在“任务效果”和“通用能力保持”之间取得平衡，微调过度可能导致灾难性遗忘或模型泛化能力下降。

## 4. 常见微调方式

### 4.1 全参数微调（Full Fine-tuning）

全参数微调会更新模型的全部参数。

优点：

- 理论上可获得较强的任务适应能力。
- 可以充分改变模型的内部表示。

缺点：

- 显存、计算和存储成本高。
- 训练大模型需要多张高性能 GPU。
- 每个任务通常都要保存一份完整模型。

因此，大模型场景中很少直接对全部参数进行微调，除非任务规模、预算和基础设施都允许。

### 4.2 LoRA 微调

LoRA（Low-Rank Adaptation）是常见的参数高效微调方法。它冻结原模型权重 `W`，只训练一个低秩增量矩阵：

```text
W' = W + ΔW
ΔW = B × A
```

其中 `A` 和 `B` 的参数量远小于原始权重 `W`。

```text
原始模型：输入 -> W -> 输出

LoRA：  输入 -> W + B×A -> 输出
                  ^
             只训练 A、B
```

优点：

- 训练参数少。
- 显存占用较低。
- 训练速度较快。
- 可以为不同任务保存不同的 LoRA Adapter，再加载到同一个基础模型上。

### 4.3 QLoRA

QLoRA 在 LoRA 的基础上进一步量化基础模型，常见做法是使用 4-bit 量化模型，同时保持 LoRA 参数以较高精度训练：

```text
4-bit 量化的基础模型
          +
      LoRA Adapter
          |
       继续训练
```

它可以进一步降低显存需求，使 7B 级别模型能够在消费级 GPU 上进行实验。实际能否运行取决于模型大小、序列长度、批大小、量化实现和显卡显存。

## 5. 微调数据格式

### 5.1 Instruction 格式

```json
{
  "instruction": "分析这段代码的问题",
  "input": "代码内容",
  "output": "存在 SQL 注入风险……"
}
```

这种格式适合描述任务指令、输入内容和期望答案。

### 5.2 Chat 格式

聊天模型更常使用 messages 格式：

```json
{
  "messages": [
    {
      "role": "user",
      "content": "什么是 RAG？"
    },
    {
      "role": "assistant",
      "content": "RAG 是检索增强生成……"
    }
  ]
}
```

实际训练时还需要根据具体模型的 Chat Template 进行格式化，否则角色标记和特殊 token 可能不匹配。

## 6. 数据质量比数据数量更重要

微调数据通常需要经过以下处理：

1. 明确任务目标和成功标准。
2. 收集真实、具有代表性的样本。
3. 清洗重复、错误、矛盾和敏感数据。
4. 统一回答格式、语气和边界。
5. 划分训练集、验证集和测试集。
6. 检查是否存在数据泄漏。

如果训练样本本身存在错误，模型会把错误的格式和结论也学进去。与其盲目增加数据量，不如先提高样本的一致性和覆盖范围。

## 7. 微调与 RAG 的区别

RAG（Retrieval-Augmented Generation，检索增强生成）把知识放在外部知识库中，回答问题前先检索相关内容，再把结果提供给 LLM。

```text
用户问题
   -> 检索知识库
   -> 获取相关文档
   -> 交给 LLM
   -> 生成答案
```

| 对比项 | RAG | 微调 |
| --- | --- | --- |
| 主要目的 | 提供外部知识 | 改变模型能力、行为或输出风格 |
| 知识位置 | 外部文档或数据库 | 模型参数中形成的表示 |
| 知识更新 | 更新知识库即可 | 通常需要重新训练或继续微调 |
| 成本 | 通常较低 | 需要训练资源和数据准备 |
| 适合场景 | 企业制度、产品文档、实时信息 | 固定任务、格式、风格和工具调用能力 |
| 可解释性 | 可以引用检索到的原文 | 较难直接追溯知识来源 |

例如，公司退款政策发生变化时，更新 RAG 知识库通常比重新微调更快、更可靠。微调可以让模型学会“如何回答退款问题”，RAG 则负责提供当前的退款政策。

实际企业系统中经常组合使用：

```text
微调：稳定行为和任务流程
RAG：注入最新、可追溯的外部知识
```

## 8. Agent 为什么可能需要微调

通用 LLM 可能知道如何回答问题，却不一定能稳定执行某个 Agent 流程。微调可以帮助模型学习固定的规划模式、工具协议和领域任务。

### 8.1 学习规划模式

例如“帮我订酒店”可以被训练成：

```text
Step 1：打开或调用搜索工具
Step 2：搜索目标城市和日期
Step 3：按照价格、评分等条件筛选
Step 4：确认信息并请求用户授权
Step 5：提交预订或返回待确认结果
```

### 8.2 提升 Tool Calling 稳定性

训练数据可以让模型更稳定地产生符合 Schema 的工具调用：

```json
{
  "tool": "weather",
  "arguments": {
    "city": "北京"
  }
}
```

工具调用微调的重点不仅是“会调用工具”，还包括：参数完整、格式合法、调用时机正确，以及工具失败后能够重试或向用户澄清。

### 8.3 构建专业 Agent

代码 Agent 可以使用类似这样的训练样本：

```text
需求描述
  -> 分析代码
  -> 修改文件
  -> 运行测试
  -> 检查结果
  -> 总结变更
```

这样可以让模型更熟悉特定的工程工作流。不过，工具权限、测试执行和结果校验仍然需要由 Agent 框架控制，不能只依赖模型记忆。

## 9. 一个完整的微调流程

```text
确定任务和评估指标
          |
       收集数据
          |
       清洗数据
          |
   构造 Instruction/Chat 数据
          |
       选择基础模型
          |
    LoRA 或 QLoRA 训练
          |
       离线评估
          |
   真实场景测试和安全评估
          |
       部署 API
```

常用工具包括：

- 训练：PyTorch、Hugging Face Transformers、PEFT、DeepSpeed
- 数据：Alpaca 格式、ShareGPT 格式及模型对应的 Chat Template
- 部署：vLLM、TensorRT-LLM、Ollama

评估时建议同时关注准确率、格式遵循度、工具调用成功率、幻觉率、延迟、成本和对原有通用能力的影响。

## 10. 面试回答版本

模型微调是在预训练大模型的基础上，利用领域数据或任务数据进行继续训练，通过调整全部或部分模型参数，使模型具备特定领域的表达能力、任务能力或输出风格。相比从零训练模型，微调成本更低；在工业界通常使用 LoRA、QLoRA 等参数高效微调方法，只训练少量新增参数。对于动态的企业知识，通常使用 RAG；对于稳定的行为、格式、工具调用和任务流程，则可以考虑微调。在企业级 Agent 中，微调和 RAG 往往结合使用。

## 11. 常见后续问题

- 什么情况下应该用 Prompt，而不是微调？
- LoRA 为什么可以减少训练参数？
- QLoRA 的量化会不会影响模型效果？
- 如何判断微调数据是否足够好？
- 微调后模型为什么会出现灾难性遗忘？
- Tool Calling 应该用微调还是 Prompt 约束？
- RAG 和微调如何组合？
- 如何评估一个微调模型是否真的有效？
