# 金钱控制台方案生成布局设计

## 目标

调整“金钱控制台”的“方案生成”页面，让用户先填写完整条件，再在页面下方阅读生成结果。生成结果使用宽版纵向卡片，并强化每个信息分组的小标题视觉层级。

## 范围

- 仅调整 `frontend/money.html` 的方案生成页面布局与样式。
- 调整 `frontend/money.js` 中方案结果的语义标记与展示 class，保持现有数据字段、API 调用和“保存为想法”交互不变。
- 不修改收入方案 API、Pydantic 模型或持久化逻辑。

## 页面结构

方案生成页从现有左右两列改为单列上下结构：

1. 顶部为“生成赚钱方案”表单。
2. 下方为“生成结果”面板。
3. 结果面板内的每个方案以独占宽度的纵向卡片呈现。

方案卡片保留现有信息顺序：

- 方案标题、方案序号、建议售价、预计成本；
- 适配理由；
- 目标客户；
- 产品/服务；
- 准备过程；
- 7 天执行计划；
- 获客方式；
- 风险挑战；
- 验证标准；
- 第一步行动；
- 成本拆分；
- 保存为想法按钮。

## 视觉设计

沿用金钱控制台现有深色主题与琥珀色主色，新增结果专用层级：

- 结果面板与方案卡片使用现有面板色和边框色，避免引入独立视觉体系。
- 方案卡片标题区域比普通列表项更突出，方案序号使用蓝色标签保留当前语义。
- 每个结果分组改为独立的信息块，使用：
  - 更醒目的小标题字号和字重；
  - 淡琥珀色或蓝色半透明背景色块；
  - 左侧强调边线；
  - 清晰的内边距和分组间距。
- 重点行动类字段（“第一步行动”）与成本字段保持同等可见度，不使用过度装饰。
- 不增加动画，不改变按钮行为，不使用会影响长文本阅读的固定高度。

## 响应式行为

- 桌面端结果信息块采用三列网格，宽版卡片占满结果面板。
- 中等宽度继续保持宽版卡片，但信息块可降为两列。
- 窄屏信息块降为单列，表单原有的单列响应式行为保持不变。
- 长标题、列表和成本拆分允许自然换行，不产生横向溢出。

## 数据与交互

- `renderPlans()` 继续消费现有 `plans` 数据。
- 所有用户可见文本继续通过现有 `esc()` 处理。
- `data-save-plan` 属性和保存接口保持不变。
- 加载中、生成失败、没有可用方案等空状态保持可见。

## 验证

- 增加前端源码回归断言，确保方案生成页使用上下结构标记，并包含结果分组样式所需的 class。
- 运行现有收入方案相关 unittest。
- 运行完整 unittest 回归。
- 若本地环境可启动服务，检查 `/money.html` 可正常返回；必要时用浏览器或截图检查桌面和移动宽度下没有重叠与溢出。
