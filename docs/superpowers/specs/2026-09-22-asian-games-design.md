# 2026 亚运会体育板块设计

## 目标

将体育页面从 NBA/世界杯演示改为 2026 年亚运会实时赛程与赛果页面：默认显示今天，支持前一天/后一天切换，并按已结束、进行中、待开始分组展示全部可获取项目。

## 方案

- 新增独立 `app/services/asian_games.py`，负责数据源请求、响应适配、北京时间转换和状态分组。
- 新增 `/api/sports/asian-games?date=YYYY-MM-DD` 后端代理；前端不直接访问第三方数据源。
- 数据源优先使用公开、可验证的实时赛事接口；响应异常或无赛事时返回明确状态，不制造静态赛果。
- 保留原有 `/api/sports/feed/{league}` 和 `/api/sports/game/{league}/{event_id}` 兼容接口，但体育页面不再调用 NBA/世界杯接口。
- `frontend/ui/sports.html` 改为亚运会专页，使用北京时间显示日期和比赛时间，按项目和状态展示赛事卡片。

## API 结构

```json
{
  "event": "2026 Asian Games",
  "date": "2026-09-22",
  "timezone": "Asia/Shanghai",
  "updated_at": "2026-09-22T12:00:00+08:00",
  "source": "...",
  "source_status": "live",
  "finished": [],
  "live": [],
  "upcoming": [],
  "total": 0
}
```

每条赛事包含 `id`、`sport`、`discipline`、`title`、`start_time`、`status`、`venue`、`participants`、`score` 和 `source_url`。未能从数据源确认的字段使用空值，不填充虚构内容。

## 状态规则

- `finished`：数据源标记赛事已结束，展示最终结果。
- `live`：数据源标记比赛进行中，展示当前比分或进度。
- `upcoming`：数据源标记尚未开始，展示北京时间开赛时间。
- 页面日期按北京时间生成和切换；接口收到非法日期时返回 400。

## 失败处理

- 数据源超时、HTTP 错误或响应结构不匹配时，后端返回 502 和可读错误；前端展示“实时数据暂不可用”。
- 合法日期但没有赛事时返回 200、空分组和 `total: 0`，前端展示“当天暂无可获取赛事”。
- 返回中保留数据源和更新时间，方便用户判断实时性。

## 安全与范围

- 后端固定数据源 URL，不接受前端传入任意 URL。
- 只读取公开赛事数据，不登录、不操作第三方网站。
- 原 NBA/世界杯接口暂不删除，避免破坏其他调用方；页面入口统一切换到亚运会。
